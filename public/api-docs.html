Endpoint

Endpoint untuk mengecek status API. Tidak perlu authentication.

Contoh Request:

  "version": "1.0.0",

2. Search Documents

GET /search

Mencari dokumen hukum di database JDIH.

Parameter:

  • q (required) - Kata kunci pencarian
  • limit (optional, default: 20) - Jumlah hasil per halaman
  • page (optional, default: 1) - Nomor halaman
  • tahun (optional) - Filter tahun terbit
  • tipe_dokumen (optional) - ID tipe dokumen (1-132)
  • status (optional) - Status dokumen (Berlaku, Dicabut, Tidak Berlaku, Diubah)
  • bidang_hukum (optional) - Bidang hukum
  • sort (optional) - Sorting (terbaru, terlama, relevansi)

Contoh Request:

curl -X GET "https://jdih.kendarikota.go.id/api/jdih/search?q=disabilitas&limit=5&tahun=2024" \
-H "X-API-Key: jdih_kendari_jdihn_permanent"

Rate Limiting

JDIHN Permanent Key: 1000 request/jam

Testing Key: 100 request/jam

Headers untuk monitoring:

  • X-RateLimit-Limit: Maximum requests per hour
  • X-RateLimit-Remaining: Remaining requests in current window
  • X-RateLimit-Reset: Unix timestamp when limit resets
  • Retry-After: Seconds to wait (if limit exceeded)

Kebijakan API Key Permanen

  • Masa berlaku: ⭐ PERMANEN - Tidak ada tanggal kadaluarsa ⭐
  • Monitoring: Aktivitas API dipantau 24/7
  • Security: Audit keamanan berkala setiap 6 bulan
  • Revokasi: Hanya jika ditemukan penyalahgunaan atau atas permintaan resmi
  • Notifikasi: Pemberitahuan 30 hari sebelum perubahan kebijakan
  • Kontinuitas: Layanan dijamin berkelanjutan untuk integrasi JDIHN

Best Practices untuk Integrasi

  1. Gunakan key permanen untuk integrasi produksi
  2. Implement retry logic dengan exponential backoff
  3. Cache responses yang tidak sering berubah (statistik, tipe dokumen)
  4. Monitor rate limits via response headers
  5. Simpan API key di environment variables, bukan hardcode
  6. Gunakan pagination untuk hasil yang banyak
  7. Error handling yang baik untuk semua kode error
